# Монтаж – правила для Claude

Этот файл Claude читает сам при каждом запуске в папке `montage`. Здесь всё, что нужно, чтобы смонтировать ролик с первого раза: порядок работы, правила вырезки дублей, правила лица, проверки перед выдачей. Правила собраны из реальных ошибок прошлых монтажей. Каждое правило закрывает ошибку, которую автор уже ловил руками.

Не спрашивать то, что здесь написано. Спрашивать только то, чего нет ни в файлах, ни в видео: ник, кодовое слово для призыва, свои скриншоты.

---

## 0. Главное за 30 секунд

1. **Расшифровка только по кускам.** Видео режется по паузам, и каждый кусок расшифровывается отдельно (`tools/transcribe.py`). Если отдать расшифровщику всю запись целиком, он склеит дубль и оригинал в одну гладкую фразу: в тексте повтора нет, а в видео он остался. Это была ошибка номер один.
2. **Решение по каждому куску.** В `cuts.json` по каждому куску записано `keep`, `cut` с причиной или частичный `keep`. Решать по «общей картине» запрещено. `cut.py` не запустится, пока хоть один кусок без решения.
3. **Дубль – оставить последнюю целую версию.** Почти всегда удачная попытка – последняя. Первые – с запинкой, смехом, оборванные.
4. **Не вырезать нужное.** Кусок, мысль которого дальше не повторяется, – не дубль. Он остаётся.
5. **После вырезки – повторная проверка** (`tools/verify.py`): готовый звук режется на кусочки ещё мельче и расшифровывается заново. Пока в `verify.md` есть ❌, дальше не идти.
6. **Лицо крупно и видно всегда.** Уменьшенное лицо – только в форме, которую задаёт стиль (в стиле ui – карточка 920×620, в стиле lesson – окно 420×420 в кадре 1920×1080, в остальных – круг диаметром от 420 px). Графика никогда не закрывает лицо.
7. **Цвет не трогать.** HDR с iPhone переводится в обычный цвет на шаге prep. Никакой цветокоррекции без просьбы.
8. **Перед выдачей – посмотреть кадры глазами** (`tools/frames.py`): каждую сцену, лицо, стыки.

## 1. Порядок работы

Все команды запускаются из папки `montage`. Python сам переключается на окружение `.venv`.

| Шаг | Команда | Что получится |
|---|---|---|
| 1. Подготовка | `python3 tools/prep.py <видео> [ещё видео…] --name <имя>` | `projects/<имя>/source.mp4`: 30 кадров/с, HDR → обычный цвет |
| 2. Сценарий | положить текст сценария в `projects/<имя>/script.txt` (если есть) | сверка «каждое предложение ровно один раз» |
| 3. Расшифровка | `python3 tools/transcribe.py <имя>` | `takes.md` (куски с подсказками), `cuts.json` (пустые решения) |
| 4. Решения | заполнить `cuts.json` по правилам раздела 3 | |
| 5. Вырезка | `python3 tools/cut.py <имя>` | `keep.json`, `cut.mp4`, `cuts.md` (что вырезано и почему) |
| 6. Проверка | `python3 tools/verify.py <имя>` | `verify.md`; ❌ → назад к шагу 4 |
| 7. План | `python3 tools/plan.py <имя> --style ui` | `phrases.md`, `plan.json`, `transcript_src.json` |
| 8. Кроп лица | `python3 tools/frames.py projects/<имя>/source.mp4 --grid` → `--crop x,y,w,h 1,10,20` | лицо крупно на всех моментах |
| 9. Сцены | дописать `plan.json` по `styles/<стиль>/STYLE.md`, скриншоты – `tools/shot.py` | |
| 10. Контрольные кадры | `python3 styles/ui/ui_reel.py projects/<имя>/plan.json --frames 1,4,8,…` | `check/ui_*.jpg` – смотреть каждый |
| 11. Рендер | `python3 styles/ui/ui_reel.py projects/<имя>/plan.json` | `final.mp4` |
| 12. Проверка готового | `python3 tools/frames.py projects/<имя>/final.mp4 --every 2` | лист кадров всего ролика |
| 13. Выдача | скопировать `final.mp4` в `готовые/<Название ролика>.mp4` | короткий отчёт автору (раздел 9) |

Шаги 1–6 делать всегда, в любом стиле. Без шага 6 видео не отдавать никогда.

Если видео записано из системы сценариев (урок 1), найти его сценарий: `~/scenarios/scripts/` или в Telegram-боте. Нашёл – положить текст в `script.txt`. Не нашёл – работать без него, не спрашивать.

Ролик из нескольких файлов (хук, начинка, призыв) – передать все файлы в `prep.py` по порядку, они склеятся.

## 2. Расшифровка

**Почему по кускам.** Расшифровщик (whisper, Scribe) подгоняет текст под «правильную» речь. Две попытки одной фразы подряд он склеивает в одну, фальстарт «я сделал… я сделал систему» превращает в «я сделал систему». Текст выглядит чистым, а в видео остаются оба дубля. Автор находит это сам и пишет «в этом месте не вырезано». Чтобы так не было:

- `transcribe.py` режет звук на куски на каждой паузе от 0,3 с, кусок не длиннее 7 с, и расшифровывает каждый отдельно. Склеивать расшифровщику нечего.
- whisper получает подсказку с запинками («Э-э, ну, это, повтор…»), поэтому пишет речь как есть, а не причёсывает её.
- Пустой кусок (расшифровщик упал по лимиту или сети) в кэш не пишется. Команда падает и просит запустить её ещё раз. Пропускать такие куски нельзя: в пустом куске может прятаться дубль.
- Кэш по каждому куску: повторный запуск бесплатный и быстрый.

**Расшифровщики** (выбираются сами в этом порядке): ElevenLabs (точнее всего пишет запинки, ключ `ELEVENLABS_API_KEY`) → Groq (бесплатный, ключ `GROQ_API_KEY` с урока 1) → whisper на компьютере (без ключа, медленнее, первый раз скачивает модель ~1,6 ГБ). Выбрать вручную: `--engine eleven|groq|local`.

**Подозрительный кусок.** Подсказка «МАЛО СЛОВ» означает, что за время куска сказано слишком мало слов. Обычно расшифровщик проглотил повтор. Перед решением разрезать мельче:

```
python3 tools/transcribe.py <имя> --split 12
```

Кусок 12 станет кусками 12.1, 12.2, … и каждый расшифруется отдельно. То же делать, если текст куска не сходится по смыслу с соседями или автор говорит, что в этом месте есть повтор.

**Две расшифровки** (если есть оба ключа): `--second` расшифровывает куски вторым движком. Куски, где движки разошлись по числу слов, помечаются в `takes.md`. Их разрезать через `--split`.

## 3. Дубли: правила решений в cuts.json

Открыть `takes.md` и идти **сверху вниз по каждому куску**. Для каждого записать решение в `cuts.json`. Не пропускать «очевидные» куски, не решать пачкой.

### 3.1. Формат решения

```json
{
  "1": {"cut": "вдох перед хуком"},
  "2": {"cut": "дубль, целая версия в #4"},
  "3": {"cut": "фальстарт «Сегодня я…», перезапись в #4"},
  "4": "keep",
  "5": {"keep": [[12.40, 13.00], [13.85, 15.10]], "why": "вырезан повтор «я сделал» внутри куска"},
  "6": {"keep": [16.20, 18.90], "why": "отрезал «блин, сначала» в начале куска"}
}
```

Время в частичном `keep` – секунды исходника, берутся из строки `слова:` под куском в `takes.md`. Граница ставится на начало слова, с которого оставляем, и на конец слова, которым заканчиваем. `cut.py` сам сдвинет её в ближайшую тишину между словами, чтобы не резать слово.

### 3.2. Что вырезать

| Что | Как узнать | Решение |
|---|---|---|
| Дубль фразы | тот же текст или та же мысль в одном из следующих 6 кусков (подсказка ДУБЛЬ, НЕДОГОВОРЁННЫЙ ДУБЛЬ) | все версии, кроме последней целой |
| Фальстарт | кусок начинается как следующий и обрывается (ФАЛЬСТАРТ, ОБРЫВОК, ОБОРВАНО) | вырезать |
| Повтор внутри куска | «я сделал я сделал систему», «это это» (ПОВТОР ВНУТРИ) | частичный `keep` без первой версии |
| Перезапуск со словами-маркерами | «ещё раз», «заново», «сначала», «стоп», «блин», «не так», «короче, давай», смех перед повтором | вырезать маркер и всё до перезапуска |
| Звуки | «э», «эм», «ммм», вдох, кашель, смех, цоканье ([вздох], (смех)) | вырезать |
| Кусок без слов | БЕЗ СЛОВ: вдох, шорох, щелчок | вырезать |
| Паузы | всё, что между оставленными кусками | `cut.py` сжимает до ~0,16 с сам |
| Тишина и вдох перед хуком | первый кусок ролика | первое слово хука звучит сразу, с первого кадра |
| Оговорка в слове | «на один… на одну» | оставить исправленный вариант |

### 3.3. Как выбрать удачный дубль

1. По умолчанию – **последний целый**: договорён до конца, без смеха, без оговорки.
2. Последний оборван или с ошибкой в слове → предпоследний целый.
3. Две целые версии одинаково чистые → последняя (автор переписывал, значит предыдущей был недоволен).
4. Нельзя склеивать начало одной попытки с концом другой, если между ними меняется интонация на полуслове. Можно, если стык попадает на паузу между предложениями.

### 3.4. Что НЕ вырезать (ошибка «вырезано нужное»)

- Кусок, мысль которого дальше нигде не повторяется. Даже если он звучит неидеально, это единственная версия.
- Импровизацию сверх сценария. Если автор сказал что-то, чего нет в `script.txt`, и это не повтор – оставить.
- Смысловую паузу, шутку, эмоцию, сказанную нарочно (например, автор сделал паузу перед панчлайном или изобразил эмоцию). Сжать паузу можно до 0,3–0,4 с, вырезать целиком нельзя.
- Последнюю версию фразы, даже если предыдущая «покороче».
- Призыв в конце и кодовое слово – проверить, что они есть в ролике целиком.

Сомневаешься, дубль это или нет – оставить и написать об этом автору в отчёте одной строкой с таймкодом.

### 3.5. Сверка со сценарием

Если в проекте лежит `script.txt`, внизу `takes.md` для каждого предложения сценария написано, в каких кусках оно сказано:
- ✅ один раз – хорошо;
- ⚠ ДУБЛИ – сказано 2+ раз, оставить одну версию (последнюю целую);
- ❌ НЕ СКАЗАНО – автор пропустил или перефразировал. Найти по смыслу, по словам не искать. Не нашёл – просто оставить так, сказать автору.

После `cut.py` и `verify.py` каждое предложение сценария должно быть в ролике ровно один раз.

### 3.6. Автор пишет «тут не вырезано»

Значит, проход по кускам что-то пропустил. Не исправлять одну точку:
1. Найти это место в `takes.md` и `verify.md` по таймкоду. Таймкод в ролике пересчитывается в исходник через `keep.json`: в `verify.md` он уже указан в скобках.
2. Сделать `--split` для этого куска **и двух соседних с каждой стороны**.
3. Перечитать весь `takes.md` заново с этим видом ошибки в голове: где ещё мог быть такой же повтор.
4. `cut.py` → `verify.py` → ответить автору, сколько ещё таких мест нашлось.

## 4. Проверка вырезки (verify.py)

`verify.py` берёт готовый `cut.mp4`, режет его на кусочки на каждой паузе от 0,12 с (не длиннее 4 с) и расшифровывает каждый заново. Проверяет:

| Проверка | Что значит ❌ |
|---|---|
| Дубли и фальстарты между кусочками | остался повтор |
| Одна и та же связка из 3–4 слов дважды в пределах 25 слов | остался повтор, который расшифровщик разбил по разным кускам |
| Паузы > 0,45 с | пауза не вырезана |
| Тишина в начале > 0,25 с | хук начинается с тишины |
| Голос на самом краю стыка (⚠) | возможно, обрезан конец или начало слова |
| Предложение сценария пропало или сказано дважды | вырезано нужное или остался дубль |
| Длина звука и видео различается | рассинхрон |

После отчёта **прочитать «Текст ролика по кусочкам» целиком**, как зритель: всё ли по смыслу, нет ли обрыва мысли, нет ли одной мысли дважды другими словами. Расшифровщик не поймает повтор «другими словами», это видно только при чтении.

❌ – исправить `cuts.json` и повторить `cut.py` → `verify.py`. ⚠ – посмотреть и решить. Пауза 0,3–0,45 с может быть смысловой, тогда оставить.

## 5. Лицо

Лицо автора – главное в ролике. Ошибки, которые уже были: лицо пропадало на целые сцены, было слишком мелким, его закрывали вставки, при уменьшении оно становилось квадратиком без формы.

1. **Лицо видно в каждом кадре.** Сцен без лица не бывает, кроме коротких (до 1,5 с) полноэкранных вставок, если их требует стиль. Нельзя брать с камеры только звук.
2. **Крупно.** В стиле ui: карточка 920×620 внизу, в интро – 1080×640 на всю ширину. В других стилях полноэкранное лицо – голова занимает 35–45 % высоты кадра.
3. **Уменьшенное лицо – в круге.** Если стиль уменьшает лицо и не задаёт свою форму (как карточка в ui), лицо идёт **кругом**: диаметр от 420 px при ширине кадра 1080, обводка 4–6 px цветом стиля, лицо по центру круга, глаза на 40 % высоты круга. Квадратик, прямоугольник без скругления и круг меньше 420 px – нельзя.
4. **Кроп лица подбирать по картинке, а не наугад.**
   - `python3 tools/frames.py projects/<имя>/source.mp4 --grid` → кадр с сеткой координат каждые 100 px. Найти глаза и подбородок.
   - Карточка ui (пропорция 920:620 = 1,48): ширина кропа ≈ вся ширина исходника, голова занимает 55–70 % высоты кропа, глаза на 35–40 % от верха кропа, подбородок целиком в кадре, лицо по центру по горизонтали.
   - Проверить: `python3 tools/frames.py projects/<имя>/source.mp4 --crop x,y,w,h 1,<середина>,<конец>`. Человек двигается, поэтому смотреть начало, середину и конец. Если на каком-то моменте голова уходит из кропа – сделать кроп свободнее.
   - Аватар HeyGen стоит ровно, ему хватает одного кадра для проверки.
5. **Графика не закрывает лицо.** Ни скриншот, ни плашка, ни слово, ни стикер. Вставки – выше лица или маленькие на уровне груди (около 720×400).
6. **На каждой сцене – контрольный кадр.** Смотреть: лицо на месте, не обрезано, крупное.

## 6. Цвет и звук

- **Цвет не трогать.** Никаких фильтров, затемнений, «тёплых» грейдов, если автор не просил. Подложку и вставки тоже не затемнять.
- **HDR.** Видео с iPhone часто снято в HDR (HLG). Обычная конвертация даёт блёклые серые цвета. `prep.py` распознаёт HDR и переводит в обычный цвет через LUT. Если автор говорит «цвета блёклые», попросить скриншот этого кадра из галереи телефона и сравнить с кадром из `source.mp4`. Сверять с галереей, а не с превью macOS: превью выцветает так же.
- **Громкость голоса** выравнивается в движке (loudnorm). Звуковые эффекты только если их требует стиль, и всегда тише голоса: эффект не должен перекрывать слова. Музыку без просьбы не добавлять.
- **Звук на всю длину.** После рендера проверить, что звук есть до конца ролика: `ffprobe` длины аудио и видео совпадают.

## 7. Субтитры и текст на экране

- Субтитры берутся из `transcript_src.json`, то есть из той же расшифровки по кускам, с точным временем каждого слова.
- **Перед рендером прочитать все слова субтитров.** Ошибки расшифровки исправить в `plan.json → fix` (слово как в расшифровке → как надо): названия сервисов латиницей (Claude, HeyGen, Instagram, Reels), «ё», цифры, имена. Если есть `script.txt`, сверить написание с ним.
- Текст на экране не добавляет утверждений, которых нет в речи. Цифр, которых автор не называл, не писать.
- Длинное тире «—» в подписях не ставить, только «–».

## 8. Стили

| Стиль | Где правила | Движок |
|---|---|---|
| `ui` (по умолчанию) | `styles/ui/STYLE.md` | `styles/ui/ui_reel.py` |
| `lesson` – горизонтальный видео-урок | `styles/lesson/STYLE.md` | `styles/lesson/lesson.py` |

- Наглядность – только настоящая: скриншоты реальных страниц (`tools/shot.py`), кадры из самого видео (`"src:12.5:card"`), материалы автора. Интерфейсы не рисовать и не подделывать. Страница закрыта входом или баннером – попросить у автора свой скриншот.
- Скопировать чужой стиль – `docs/copy-style.md`.

## 9. Перед выдачей (чек-лист, все пункты)

- [ ] `verify.py` без ❌, все ⚠ просмотрены.
- [ ] Текст ролика прочитан целиком: нет повтора мысли, нет обрыва.
- [ ] Каждое предложение сценария есть ровно один раз (если есть `script.txt`).
- [ ] Первое слово звучит с первого кадра.
- [ ] Контрольные кадры на каждую сцену просмотрены: лицо крупно, не обрезано, ничем не закрыто.
- [ ] Лист кадров всего ролика (`frames.py final.mp4 --every 2`) просмотрен: нет пустых кадров, чёрных вставок, замёрзших картинок.
- [ ] Субтитры прочитаны: нет ошибок в словах и названиях.
- [ ] Длины звука и видео совпадают, звук есть до конца.
- [ ] Ролик короче 60 с. Если длиннее – сказать автору, что можно сократить (не резать смысл самому).
- [ ] Готовый файл скопирован в `готовые/<Название>.mp4`.

**Отчёт автору** – коротко, без пересказа процесса:
```
Готово: готовые/<Название>.mp4, 0:47.
Вырезано: 9 дублей, 4 фальстарта, 12 вдохов и пауз (список – projects/<имя>/cuts.md).
Под вопросом: 0:21 – «…» оставил, похоже на нарочную паузу.
```
